# 🌾 PaddyCare AI — Premium Agritech

**Indonesia + English** Streamlit client for the existing ten-class EfficientNet-B0 rice classifier.
This is a runnable code package, **not a trained model**. Supply your authentic `.pth` file first.

## What's included

- **Streamlit**: premium emerald UI, upload/camera, Indonesian-English language switch, diagnosis confidence, top 3 predicted classes, low-confidence warning, treatment steps, disease knowledge hub, download summary, analytics and history.
- **FastAPI**: `POST /predict`, `GET /health`, `GET /history`, `GET /stats`, `GET /classes`, API docs at `/docs`.
- **SQLite**: stores prediction IDs, labels, full softmax probabilities, confidence, timestamps — **not photos or personal information**.
- **CI/CD groundwork**: GitHub Actions tests on push/PR; optional Render deploy-hook workflow after successful CI.
- **Agronomy**: cautious and editable static information for all 10 labels, with institutional sources; not generated by an LLM.

## 1. Important: preparing the model

The `.pth` from the notebook already verified by the user contains only `classifier_state_dict` (9 tensors) and metadata. The deployment service needs the ImageNet-pretrained **backbone** weights as well. **You do not need to retrain the classifier.**

### Option A — existing head-only checkpoint, Kaggle or online laptop (recommended)

Put your existing head-only checkpoint in a known path (e.g. `/kaggle/working/old_paddycare_model.pth`). In a Kaggle cell or local terminal with `torch` and `torchvision` installed:

```bash
python scripts/upgrade_checkpoint.py --input /kaggle/working/old_paddycare_model.pth --output /kaggle/working/paddycare_model.pth
```

On Windows, adapt the paths, e.g. `python scripts/upgrade_checkpoint.py --input old_paddycare_model.pth --output models/paddycare_model.pth`.

This downloads `EfficientNet_B0_Weights.IMAGENET1K_V1` **once** if necessary. The training notebook used `EfficientNet_B0_Weights.DEFAULT`, which maps to this weight version at the checked torchvision version. Make sure Kaggle internet is enabled. This creates a standalone checkpoint with both backbone and head.

If you still have the **original trained** `backbone` and `head` objects active in Kaggle, you can instead re-export both `state_dict` objects in a single checkpoint as shown previously. Do **not** reset/re-initialize the classifier head before exporting.

### Option B — already exported full checkpoint

Copy it directly to `models/paddycare_model.pth`.

**Must-have fields**: `model_architecture`, `feature_dim`, `num_classes`, `class_to_idx`, `image_size`, `mean`, `std`, `dropout`, `backbone_state_dict`, and `classifier_state_dict`.

⚠️ Verify checkpoint provenance. Only load checkpoint files created by you or a trusted source.

## 4. Important interpretability notes

- The model's 93.66% accuracy and 93.57% macro F1 are aggregate holdout-test results from the user's notebook, NOT per-image accuracy.
- UI confidence is softmax output, which can be overconfident without calibration.
- A low-confidence warning appears if the top class has `<65%` probability **or** the top-two gap is `<15 percentage points`. These are **illustrative UX thresholds only**, not scientifically validated thresholds. Tune/calibrate using separate validation data before real decisions.
- `dead_heart` is a symptom often associated with stem borers; `hispa` is a pest and `normal` does not prove freedom from disease.
- Disease templates provide staged scouting, monitoring and prevention. They should be reviewed by an Indonesian agronomist and localized before farmer-facing production use. No pesticide products/dosages are automatically prescribed.

## 5. API security and moving from local to public

**Do not expose the development API or history to the internet without safeguards.** Local use binds the API to `127.0.0.1`.

Example environment variables for a separate hosted backend:

- `MODEL_PATH=/var/data/paddycare_model.pth` (private storage; not committed to Git)
- `DB_PATH=/var/data/paddycare.db` (persistent disk)
- `PADDYCARE_API_KEY=<long_random_value>` (set in host dashboard; same value in Streamlit host env)
- `PADDYCARE_PUBLIC_MODE=1` (set on **both** backend and frontend to disable per-record history for visitors; aggregate analytics remains visible)

The client reads `API_URL` (set to hosted HTTPS FastAPI URL) and `PADDYCARE_API_KEY` server-side. HTTPS required. When API key is configured, `/predict`, `/classes`, `/stats`, `/history` are protected at the backend by `X-API-Key`.

**Note:** an API key protects the backend from direct clients, but a *public Streamlit instance* can still expose its history tab to anyone visiting the site. Set `PADDYCARE_PUBLIC_MODE=1` on both apps to hide per-record history while showing aggregates; add per-user authentication and audit retention/privacy policy before real multi-user production use. SQLite requires persistent storage and is best for single-instance deployment; use PostgreSQL for scaling.

### Suggested online path

1. Create a **private** GitHub repository, push this code, and retain your `.pth` file outside Git (excluded via `.gitignore`).
2. Host FastAPI on a Python-capable platform such as Render with persistent disk/model storage; startup command `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`. Load your model to the private disk and set `MODEL_PATH`.
3. Host Streamlit via Streamlit Community Cloud (if compatible with your private repo and service requirements; lightweight UI dependencies are in `frontend/requirements.txt`) or the same infrastructure, startup command `streamlit run frontend/app.py --server.address 0.0.0.0 --server.port $PORT`. Set `API_URL` and API key as secret environment variables.
4. Add `RENDER_DEPLOY_HOOK_URL` to your GitHub repository Secrets only once remote backend deployment has been created; after CI passes, `deploy.yml` can trigger the Render deployment. Streamlit Cloud deployments depend on your linked repository settings.
5. Validate photo inference, latency, history access, and persistent database under the actual hosting plan before sharing publicly.

The repository includes CI and an *optional* CD hook; public deployment is **not automatically configured** until you supply host credentials, model storage, and URLs.
